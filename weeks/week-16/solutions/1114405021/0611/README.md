# Week 16 Sorting Performance Lab

## Summary

This solution implements the five stages from the handout:

1. `timeit` decorator with `last_elapsed` and `records`
2. Three baseline sorting algorithms plus benchmark collection
3. Optimized sorting variants for comparison against `sorted()`
4. Plot generation with log-scale y axis
5. Security self-scan tests for input validation, safe file handling, and no printing from the timing decorator

## How to run

```bash
python test_timing.py
python test_sorts.py
python benchmark.py
python plot.py
python test_plot.py
python test_security.py
```

## Benchmark report

Run `python benchmark.py` to regenerate `results.json`, then run `python plot.py` to update `assets/benchmark.png`.

The optimized version uses algorithmic improvements rather than Cython, so it stays portable and avoids build artifacts.

Observed results on this environment:

| algorithm | 500 | 1000 | 2000 | 4000 |
|---|---:|---:|---:|---:|
| bubble_sort | 0.015480 | 0.056282 | 0.215810 | 0.932130 |
| quick_sort | 0.000806 | 0.002193 | 0.003476 | 0.008004 |
| merge_sort | 0.000885 | 0.003088 | 0.006158 | 0.013456 |
| sorted | 0.000061 | 0.000123 | 0.000261 | 0.000620 |
| bubble_sort_fast | 0.013161 | 0.066471 | 0.247604 | 1.135906 |
| quick_sort_fast | 0.000597 | 0.001120 | 0.002806 | 0.006479 |
| merge_sort_fast | 0.001288 | 0.003802 | 0.006089 | 0.012800 |

The clearest speedup comes from `quick_sort_fast`, which is about 1.24x to 1.96x faster than the baseline `quick_sort` across the measured sizes, and much faster than `bubble_sort`.
