# UVA 11321 — 動態放陷阱與道路是否封死

## 題目敘述

紅圓茵可家門前有一條長方形柏油路。

柏油路被切成 N × M 個格子。

- 縱軸是 x 軸
- 橫軸是 y 軸
- 左下角是座標 (0, 0)

也就是說：

- x 的範圍是 0 到 N - 1
- y 的範圍是 0 到 M - 1

柏油路的起點在左邊，茵可家在右邊。

人可以在柏油路上往四個方向移動：

    上、下、左、右

不能走斜對角。

茵可想依序在某些格子放陷阱。

如果踩到陷阱，就不能正常通過，所以陷阱可以視為障礙物。

每次茵可想放一個陷阱時，我們要判斷：

- 如果放下去之後，仍然存在從左邊走到右邊的路徑，則可以放。
- 如果放下去之後，會讓左邊到右邊完全不連通，則不能放。

---

## 輸入格式

第一行有三個正整數：

    N M T

代表：

- N：柏油路高度，也就是 x 方向格子數
- M：柏油路寬度，也就是 y 方向格子數
- T：接下來要嘗試放的陷阱數量

接下來 T 行，每行有兩個非負整數：

    x y

代表想要在座標 (x, y) 放陷阱。

題目保證同一個點最多只會被嘗試放一次。

---

## 輸出格式

對每一個要放的陷阱：

如果該陷阱可以放，輸出：

    <(_ _)>

並且真的把陷阱放上去。

如果該陷阱不能放，輸出：

    >_<

並且不要把陷阱放上去。

---

## 解題核心觀念

題目問的是：

    放陷阱後，是否還存在從左邊到右邊的道路？

如果每次都用 BFS 或 DFS 去檢查左邊能不能到右邊，最壞情況會很慢。

因為 N、M 最大可到 1000，總格子數可能有：

    1000 × 1000 = 1,000,000

如果每次放陷阱都重新搜尋整張地圖，效率會太差。

---

## 關鍵轉換：看陷阱是否形成上下阻隔牆

人在空格中只能走：

    上、下、左、右

所以如果要阻止人從左邊走到右邊，陷阱必須形成一道從上邊界連到下邊界的牆。

只要陷阱形成「上到下」的連續障礙，就會把柏油路切開，使左邊無法到右邊。

因此，問題可以轉換成：

    每次放陷阱後，檢查陷阱是否形成從上邊界到下邊界的連通區塊。

如果形成，就不能放。

如果沒有形成，就可以放。

---

## 為什麼陷阱要用 8 方向連通？

人走路只能走 4 方向，不能斜走。

但是陷阱形成牆時，斜角相接也可能阻擋 4 方向通行。

例如 2 × 2 格子：

    x .
    . x

其中 x 是陷阱。

兩個陷阱雖然只是斜角相連，但剩下兩個空格也只斜角相鄰，人不能斜走，所以路已經被擋住。

因此：

- 人的移動是 4 方向
- 陷阱的阻隔連通要看 8 方向

陷阱的 8 方向包含：

    上、下、左、右、左上、右上、左下、右下

---

## 使用資料結構：Disjoint Set Union

為了快速維護陷阱是否形成連通區塊，可以使用 Disjoint Set Union，也就是並查集。

並查集可以快速處理：

1. 新增一個陷阱
2. 將它和周圍已存在的陷阱合併
3. 查詢某個陷阱連通區塊是否碰到上邊界或下邊界

---

## DSU 中需要記錄什麼？

每個陷阱連通區塊除了 parent 和 size 之外，還要記錄：

    touch_top[root]
    touch_bottom[root]

其中：

- touch_top[root] 表示這個陷阱區塊是否碰到上邊界
- touch_bottom[root] 表示這個陷阱區塊是否碰到下邊界

如果某個陷阱區塊同時滿足：

    touch_top[root] == True
    touch_bottom[root] == True

代表陷阱已經形成從上到下的阻隔牆。

此時左邊到右邊的道路會被封死。

---

## 如何判斷某個新陷阱能不能放？

假設要嘗試放陷阱在座標：

    (x, y)

我們先不要真的放。

先檢查：

1. 這個新陷阱本身是否碰到上邊界或下邊界。
2. 它周圍 8 個方向有哪些已經存在的陷阱。
3. 把這些相鄰陷阱所在連通區塊的 touch_top 和 touch_bottom 合併來看。
4. 如果合併後同時碰到上邊界和下邊界，代表這個陷阱一放就會封死道路，所以不能放。
5. 否則可以放，並且把它加入 DSU，再與周圍陷阱合併。

---

## 邊界判斷

座標 x 是縱軸。

因為左下角是 (0, 0)，所以：

- x = 0 是下邊界
- x = N - 1 是上邊界

因此：

    如果 x == 0，代表碰到底部
    如果 x == N - 1，代表碰到頂部

只要某個陷阱連通區塊同時碰到底部與頂部，就會封死左到右的路。

---

## 演算法步驟

對每一個陷阱位置 (x, y)：

1. 預設 new_touch_top = x == N - 1。
2. 預設 new_touch_bottom = x == 0。
3. 檢查周圍 8 個方向。
4. 如果鄰居位置已經有陷阱：
   - 找出它的 DSU root。
   - 合併該 root 的 touch_top / touch_bottom 狀態。
5. 如果合併後同時 touch_top 和 touch_bottom：
   - 輸出 `>_<`
   - 不放陷阱
6. 否則：
   - 輸出 `<(_ _)>`
   - 啟用該格子為陷阱
   - 設定它的 DSU 狀態
   - 與周圍已存在的 8 方向陷阱合併

---

## 時間複雜度

每次放陷阱只需要檢查 8 個方向。

DSU 的 find 和 union 幾乎可以視為常數時間。

所以每次操作約為：

    O(1)

總共有 T 次操作，因此總時間複雜度為：

    O(T)

---

## 空間複雜度

需要為 N × M 個格子準備 DSU 陣列與 active 陣列。

空間複雜度為：

    O(N × M)

當 N、M 最大為 1000 時，最多是 1,000,000 個格子，仍可接受。

---

## 測試用例

### 測試輸入 1

    3 3 3
    0 1
    1 1
    2 1

### 預期輸出 1

    <(_ _)>
    <(_ _)>
    >_<

說明：

前兩個陷阱可以放。

第三個陷阱放在 (2, 1) 後，會和原本 (0, 1)、(1, 1) 形成從下到上的直線牆，封死左到右道路，因此不能放。

---

### 測試輸入 2

    2 2 2
    0 0
    1 1

### 預期輸出 2

    <(_ _)>
    >_<

說明：

第二個陷阱雖然只是和第一個陷阱斜角相鄰，但陷阱阻隔要看 8 方向。

放下第二個陷阱後會形成上下阻隔，因此不能放。

---

## 重點提醒

本題容易錯的地方：

1. 人走路是 4 方向。
2. 陷阱形成牆要用 8 方向判斷。
3. 要檢查的是陷阱是否連接上邊界與下邊界。
4. 如果會封死道路，該陷阱不能真的放進 DSU。
5. 座標 x 是縱軸，x = 0 是下邊界，x = N - 1 是上邊界。
