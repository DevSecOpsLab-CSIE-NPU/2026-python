# 0617 搜尋效能評估

## 量測結果 (n = 1,000,000, target = 999,999)

| 方法 | 平均耗時 |
|------|---------|
| linear_search | 0.027860 s |
| binary_search | 0.000003 s |
| sort + binary_search | 0.179293 s |

## 評估

1. **誰快？差多少？** — binary_search 比 linear_search 快約 **9,000 倍**（0.028s vs 0.000003s），因為 linear 在最壞情況要走完整個 list，而 binary 只需 log₂(n) ≈ 20 次比較。

2. **排序 + binary 划不划算？** — 單次查詢不划算。排序花了 ~0.18 秒，比 linear 最壞情況（0.028s）還慢。但如果要查詢**很多次**，排序成本就能攤平，之後每次 binary 都只需要 3μs，遠快於 linear 的 28ms。

3. **直覺** — 排序 + binary 的交叉點大概在「查詢次數 ≥ 10 次左右」：排序 0.18s ÷ (linear 0.028s − binary 0.000003s) ≈ 6.4 次。也就是說如果查詢 7 次以上，先排序再 binary 就開始划算了。（明天用完整實驗數據驗證）
