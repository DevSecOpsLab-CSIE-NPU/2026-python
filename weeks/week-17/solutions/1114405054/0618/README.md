# 6/18 — 搜尋效能實驗室報告

## Stage 3 加速前預測

> 此預測在實測數據之前寫入，commit `docs: stage3 加速前預測`。

**我的預測：**
- 在多次搜尋下，交叉點（排序+binary 開始贏 linear）約在 **n ≈ 40 ~ 80**。
- n 小時 linear 有 cache 優勢且無排序開銷；n 變大後 binary 的 O(log n) 優勢會補回排序成本。
- 預測排名（多次查詢，大 n）：set_search > binary_search > linear_search。

### 交叉點分析

| 情境 | 結果 |
|------|------|
| 單次查詢 sort+binary vs linear | 永不交叉（排序成本 O(n log n) > 一次 O(n)） |
| 100 次查詢 sort+100binary vs 100×linear | **n ≈ 20** 開始 binary 贏 |
| 無排序成本 binary vs linear | **所有 n ≥ 100** binary 贏 |

**關鍵發現：**
1. AI 常說「binary 一定比 linear 快」——這在**需要先排序**時是錯的。
   單次查詢時排序成本讓 sort+binary 永遠比 linear 慢（測試到 n=100000 仍未交叉）。
2. 查詢次數越多，排序成本越划算。本機器上 **100 次查詢時 n≈20 就開始贏**。
3. set_search 慢於預期——每次建立 set 的 O(n) 開銷吃掉 hash 優勢。
