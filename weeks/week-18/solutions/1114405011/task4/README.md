# 第四題：搜尋演算法多維度效能權衡分析 (README)

本實驗針對「線性搜尋 (Linear Search)」與「二分搜尋 (Binary Search)」在不同維度上的表現進行量化評估，並將結果繪製成雷達圖（儲存於 `assets/radar.png`）。

## 1. 權衡維度與正規化說明

我們自訂了 4 個計算機科學核心維度，評分範圍為 1~5 分（分數越高代表表現越優異、對開發者越有利）：

1. **Small N Speed（小數據量下的搜尋速度）**
   - **線性搜尋 (5分)**：不需經過任何排序，直接走訪，在資料量極小時 Overhead 最小。
   - **二分搜尋 (4分)**：雖然速度也極快，但需要計算中間索引與邊界跳躍，存在微小的常數時間 Overhead。
2. **Large N Speed（大數據量下的搜尋速度）**
   - **線性搜尋 (1分)**：時間複雜度為 $O(N)$，當資料量放大到 $10^5$ 以上時，耗時呈線性暴增。
   - **二分搜尋 (5分)**：時間複雜度為 $O(\log N)$，即使資料量極大，也能在極少次數內鎖定目標。
3. **Worst Case Cmp（最壞情況下的比較次數）**
   - **線性搜尋 (1分)**：最慘需要比較 $N$ 次。
   - **二分搜尋 (5分)**：最慘只需要比較 $\lfloor\log_2 N\rfloor + 1$ 次。
4. **Simplicity（演算法實作與前提簡易度）**
   - **線性搜尋 (5分)**：程式碼僅需一個迴圈，且**完全不需要事先排序**，隨來隨找。
   - **二分搜尋 (3分)**：實作邏輯需小心邊界（Low/High 調整），且**強制要求資料必須是已排序狀態**，維護成本較高。

## 2. 實驗數據與真實解讀

在本次機考的特定實驗中，我們觀測到了非常經典的特例數據：
- **二分搜尋比較次數**：`cmp=18`
- **線性搜尋耗時**：`0.00006 s`
- **二分搜尋耗時**：`0.00015 s`
- **結論**：`=> linear faster`

### 💡 數據背後的關鍵解讀：
雖然本實驗產生了高達 200,000 筆的大型陣列，理論上應是二分搜尋壓倒性獲勝。然而，因為隨機生成的搜尋目標 `K = 111` 恰巧被排在陣列的極前端（索引值 `idx = 19`）。

這導致**線性搜尋僅僅比較了 20 次就成功命中目標**，幾乎觸及了線性搜尋的 Best Case（最佳情況）；而二分搜尋依然老老實實地切半、計算 `mid`，一共比較了 18 次。在比較次數極度接近的情況下，線性搜尋因為沒有切半與邊界指標移動的常數 Overhead，因而在 `timeit` 測量中跑出了比二分搜尋更快的速度。

**結論：沒有絕對完美的演算法，只有最適合當下情境的選擇。這正是計算機科學進行多維度權衡（Trade-off）的迷人之處。**
