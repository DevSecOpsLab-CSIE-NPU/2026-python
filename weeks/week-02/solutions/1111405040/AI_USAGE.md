# AI 協助使用說明

## 概述

本作業在開發過程中適度使用 AI 協助，但所有最終代碼都經過驗證和調整，確保正確性和可解釋性。

---

## AI 使用情況

### 1. Task 1：Sequence Clean

#### 使用場景
- **設計測試案例**：使用 AI 幫助想出邊界情況（全重複、全偶數、無偶數）
- **程式框架**：AI 建議使用 set 追蹤已見元素，保留去重順序

#### AI 建議 vs. 最終實作
| 方面 | AI 原始建議 | 調整原因 | 最終實作 |
|------|-----------|--------|--------|
| 去重方式 | 使用 dict.fromkeys() | dict 在 3.7+ 保留順序，但 set 更直觀 | set + 列表迴圈 |
| 排序鍵 | 使用 operator.itemgetter | 簡單情況不需，直接用 sorted() 即可 | sorted() 內建 |
| 測試個數 | 每個函式 3 個 | 多加整合測試 | 每個函式 3 個 + 整合測試 |

#### 驗證方法
- 手動測試 HOMEWORK 範例輸入
- 確認邊界情況（單一元素、全重複、無偶數）
- 檢查輸出格式符合規範

---

### 2. Task 2：Student Ranking

#### 使用場景
- **排序邏輯**：AI 幫助設計複雜的多鍵排序
- **測試案例**：AI 建議測試相同分數的邊界情況

#### AI 建議 vs. 最終實作
| 方面 | AI 原始建議 | 調整原因 | 最終實作 |
|------|-----------|--------|--------|
| 排序鍵 | 使用 cmp 函式 | Python 3 不支援 cmp，用 key 替代 | lambda x: (-x[1], x[2], x[0]) |
| K 值處理 | 檢查 k > len(list) | Python slice 自動處理 | 直接 students[:k] |
| 驗證 | 只驗證正常情況 | 需要邊界情況測試 | 增加 k=0, k>n 測試 |

#### 驗證方法
- 使用 HOMEWORK 範例手動驗證排序順序
- 測試邊界情況（k > n, k = 0）
- 確認同分時年齡優先於名字

---

### 3. Task 3：Log Summary

#### 使用場景
- **計數方式**：AI 建議使用 defaultdict vs Counter
- **排序邏輯**：AI 幫助設計「事件數多 → 少，名字 a → z」的排序

#### AI 建議 vs. 最終實作
| 方面 | AI 原始建議 | 調整原因 | 最終實作 |
|------|-----------|--------|--------|
| 計數工具 | Counter | defaultdict 也可，本作業兩個都用示範 | defaultdict(int) |
| 最常見動作 | 使用 max() 函式 | Counter.most_common(1) 更簡潔 | Counter.most_common(1) |
| 排序 | 手寫 cmp | 使用 lambda key | lambda x: (-x[1], x[0]) |

#### 驗證方法
- 使用 HOMEWORK 範例驗證使用者計數和排序
- 確認 login 確實是最常見動作（3 次）
- 測試相同計數時名字排序

## AI 協助失效的情況與修正

### 1. Dict vs Set 去重
**失效**：AI 建議使用 `dict.fromkeys(list)`，雖然正確但不夠直觀
**修正**：改用 `set + 列表迴圈` 明確表達邏輯

### 2. Cmp 函式
**失效**：AI 提到 Python 2 的 cmp，但 Python 3 已移除
**修正**：改用 `lambda key` 搭配 sorted()

### 3. 測試數量
**失效**：AI 初始建議每個函式 3 個測試
**修正**：增加整合測試和邊界測試，達到 27 個

## 學習心得

### 規格拆解
- AI 幫助理解排序規則的優先級
- 通過寫測試案例加深對問題的理解

### 測試設計
- AI 提示考慮邊界情況（k=0, 全重複、無偶數）
- 自己思考「什麼會錯」的情景

### 結果驗證
- 比對 HOMEWORK 範例與實際輸出
- 手動執行小規模測試確認邏輯

### 錯誤復盤
- AI 建議失效時，主動改用更簡潔的方式
- 每個修改都經過測試驗證
