# 程式碼優化優缺點總結 (Optimizations Summary)

## 10226 (DFS 排列組合問題)
- **優點**: 使用了批次輸出 (`sys.stdout.write("\n".join(out))`) 取代頻繁的 `print()`，大幅減少了 I/O 操作的時間開銷，讓大量輸出時的執行速度更快。
- **缺點**: 由於需要將所有結果暫存到記憶體中的 `out` 陣列再統一印出，如果排列結果超級多，會增加峰值記憶體 (Peak Memory) 的消耗。

## 10235 (插座與蛇的方格放置問題)
- **優點**: 引入了 Python 內建的 `@lru_cache(None)` 來取代手動維護的 `memo` 字典。底層由 C 語言實作，緩存查詢速度比原本的 Python dictionary 查找要快得多，且代碼更簡潔。
- **缺點**: 遞迴深度如果過深，仍然可能遇到 `RecursionError`，且 `@lru_cache` 無法像手動字典那樣容易在多組測試資料間精確清理（雖然這裡以每次迴圈重新定義函數來避開問題，但也帶來微小的重新建立函數的開銷）。

## 10242 (ATM搶劫路線最大化)
- **優點**: 將第一次的正向 DFS 改寫為「迭代版本 (Iterative)」，利用迴圈搭配 Stack 來代替遞迴呼叫。徹底解決了 Python 的遞迴深度限制問題 (`RecursionError`)，也節省了 Call stack 的空間與時間開銷。
- **缺點**: 迭代版的 DFS 邏輯（尤其是需要記錄離開順序的後序走訪）較為複雜，可讀性不如原本純粹的遞迴版本直觀，對初學者來說較難理解與維護。

## 10252 (兩條線的距離最小化問題)
- **優點**: 將原本的「爬山演算法/模擬退火」改為數學上更精準的「Weiszfeld's algorithm (求幾何中點)」。此演算法收斂速度極快，通常不到 100 次迭代就能達到極高精度，大幅減少了時間複雜度。
- **缺點**: Weiszfeld 演算法在遇到「當前猜測點剛好落在某個資料點」上時會有除以零的問題（需用 `dist > 1e-8` 等特判來迴避），另外實作數學公式較為死板，不如爬山演算法具備應付各種奇形怪狀函數的萬用性。

## 10268 (丟水球問題)
- **優點**: 將 `sys.stdin` 逐行讀取改為 `sys.stdin.read().split()` 一次讀取並透過批次處理輸出 (`\n.join()`)，顯著提升了處理大量測資時的 I/O 效率。
- **缺點**: 需要一次把所有測資讀進記憶體，如果測資檔案是幾十 MB 的超大文字檔，可能會短暫佔用較多記憶體空間。
