easy.py 程式優化與偵錯說明

一、這支程式在做什麼

這支程式是在解「有向圖 + 強連通分量 SCC + DAG 最長路」的題目。

題目的概念是：

1. 有 n 個點、m 條有向邊
2. 每個點都有一筆金額
3. 從指定起點 start_node 出發
4. 目標是走到某個有酒吧的點
5. 路上可以收集經過點的金額
6. 要求最多可以收集多少錢

因為在同一個強連通分量 SCC 裡面，
點和點之間可以互相到達，
所以只要進入同一個 SCC，
就可以把這個 SCC 裡所有點的錢都拿完。

因此程式會先找 SCC，
再把 SCC 縮成一個點，
最後在縮點後的 DAG 上做最長路 DP。


二、使用到的主要演算法

【1】Kosaraju 演算法找 SCC

這份程式使用 Kosaraju 演算法。

Kosaraju 分成兩步：

第一步：
在原圖上 DFS，取得 finishing order。

第二步：
按照 finishing order 的反向順序，
在反圖上 DFS，
找出每一個 SCC。


【2】縮點

找到 SCC 之後，
原本的每個點都會有一個 comp_id。

如果一條邊 u -> v，
而且 u 和 v 不在同一個 SCC，
就建立一條 SCC 之間的邊：

comp_id[u] -> comp_id[v]

這樣就可以得到一張 DAG。


【3】DAG 最長路 DP

縮點後的圖是 DAG，
所以可以用拓樸排序做 DP。

dp[c] 表示：
從起點 SCC 走到 SCC c 時，
最多可以拿到多少錢。

最後答案就是：
所有有酒吧的 SCC 裡面，
dp 最大的值。


三、我做了哪些優化

【1】保留非遞迴 DFS

Python 的遞迴深度有限，
如果圖很大，使用遞迴 DFS 可能會發生：

RecursionError

所以這份程式使用 stack 模擬 DFS，
避免遞迴爆掉。

這是很重要的穩定性優化。


【2】使用陣列建立鄰接串列

程式沒有使用 list 裡面放 list 的一般寫法，
而是用：

head
to
nxt

這種陣列方式建立圖。

好處是：

1. 記憶體使用比較穩定
2. 適合大量邊的題目
3. 速度通常比較快
4. 比較接近競賽寫法


【3】同時建立原圖與反圖

Kosaraju 需要原圖和反圖。

原圖用來求 finishing order。
反圖用來找 SCC。

所以輸入邊 u -> v 時，
同時加入：

原圖：u -> v
反圖：v -> u


【4】加強變數命名

原本一些變數比較短，例如：

s
p
cu
cv
ans

我改成比較清楚的名字：

start_node
bar_count
u_comp
v_comp
answer
indegree

這樣比較容易看懂程式在做什麼。


【5】加入詳細繁體中文註解

這份程式包含很多演算法概念，
所以我補上了詳細註解。

註解包含：

1. add_edge 的用途
2. head、to、nxt 的意思
3. finishing order 是什麼
4. SCC 是什麼
5. 為什麼要縮點
6. DAG 上的 dp 代表什麼
7. 最後答案怎麼找


【6】保留 deque 做拓樸排序

拓樸排序需要一直從前面取出節點，
所以使用 deque 比 list 更適合。

使用：

queue.popleft()

時間複雜度是 O(1)。

如果用 list.pop(0)，會比較慢。


四、偵錯後確認

【1】可以正確讀取 n、m

第一行會讀入：

n m

代表點數和邊數。


【2】可以正確讀取 m 條邊

每條邊 u -> v 都會被加入原圖，
同時也會加入反圖 v -> u。


【3】可以正確讀取每個點的金額

money[i] 表示第 i 個點可以取得的錢。


【4】可以正確標記酒吧節點

is_bar_node[node] = True

表示這個點是酒吧。


【5】可以正確找出 SCC

第一階段：
原圖 DFS 產生 finishing order。

第二階段：
反圖 DFS 產生 comp_id。


【6】可以正確計算每個 SCC 的總金額

同一個 SCC 裡所有點的 money 會加總到：

comp_money[comp_id]


【7】可以正確判斷 SCC 是否有酒吧

只要 SCC 裡面任一點是酒吧，
comp_has_bar[comp_id] 就會是 True。


【8】可以正確建立縮點 DAG

如果 u 和 v 不同 SCC，
就建立：

u_comp -> v_comp


【9】可以正確做最長路 DP

如果 dp[u] 不是 -1，
代表起點可以走到 u。

接著用：

dp[v] = max(dp[v], dp[u] + comp_money[v])

更新答案。


【10】最後答案正確

只從有酒吧的 SCC 裡面找最大 dp 值，
因為題目要求最後要走到酒吧。


五、時間複雜度

假設：

n 是點數
m 是邊數

整體時間複雜度約為：

O(n + m)

原因是：

1. 建圖需要 O(m)
2. Kosaraju DFS 需要 O(n + m)
3. 建立 DAG 需要 O(m)
4. DAG DP 需要 O(n + m)

所以這份程式適合處理大型圖。


六、空間複雜度

主要使用：

1. 原圖 head、to、nxt
2. 反圖 rev_head、rev_to、rev_nxt
3. comp_id
4. dp
5. dag

空間複雜度約為：

O(n + m)


七、總結

這次優化主要是讓程式更清楚、更穩定、更適合交作業。

保留原本正確的核心演算法：

1. Kosaraju 找 SCC
2. SCC 縮點
3. DAG 拓樸排序
4. 最長路 DP

並改善：

1. 變數命名
2. 繁體中文註解
3. 程式可讀性
4. 偵錯說明
5. 大型資料穩定性

整體來說，這份程式是競賽題常見的標準解法。
