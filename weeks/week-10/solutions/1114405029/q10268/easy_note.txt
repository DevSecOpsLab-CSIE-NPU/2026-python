easy.py 程式優化與偵錯說明

一、這支程式在做什麼

這題是經典的「丟球測樓層」問題。

給定：

1. ball_count 顆球
2. floor_count 層樓

目標是找出：
最少需要幾次試驗，才能保證在最壞情況下測出臨界樓層。

如果需要超過 63 次，
就輸出：

More than 63 trials needed.


二、核心觀念

這題不是直接問：

有 k 顆球、n 層樓，要怎麼測？

而是反過來想：

如果我有 trials 次試驗，
又有 balls 顆球，
最多可以測幾層樓？


三、DP 狀態定義

dp[balls] 表示：

在目前 trials 次試驗內，
使用 balls 顆球最多可以測幾層樓。


四、DP 轉移公式

每次多一次試驗時：

dp[balls] = dp[balls] + dp[balls - 1] + 1

意思是：

1. 如果這次丟球沒破
   可以繼續往上測
   範圍是 dp[balls]

2. 如果這次丟球破了
   剩下 balls - 1 顆球
   可以往下測
   範圍是 dp[balls - 1]

3. 目前這一層本身也算 1 層

所以總共可以測：

上面範圍 + 下面範圍 + 目前這層

也就是：

dp[balls] + dp[balls - 1] + 1


五、為什麼要從大到小更新

程式裡面使用：

for balls in range(ball_count, 0, -1):

一定要從大到小更新。

原因是：

dp[balls] 需要用到「上一輪 trials」的 dp[balls - 1]。

如果從小到大更新，
dp[balls - 1] 會先被改掉，
就會拿到錯誤資料。

所以必須從大到小更新，
才能保留上一輪的狀態。


六、我做了哪些優化

【1】變數名稱更清楚

原本使用：

k
n
eggs

我改成：

ball_count
floor_count
balls

因為題目是球，不一定是雞蛋。
這樣比較符合題意，也比較好懂。


【2】保留一維 DP

原本程式已經使用一維 DP，
這是很好的寫法。

如果使用二維 DP，
空間會比較大。

一維 DP 可以把空間壓到：

O(ball_count)


【3】保留 63 次限制

題目規定如果超過 63 次，
就要輸出：

More than 63 trials needed.

所以程式使用：

LIMIT = 63

讓限制值集中管理。


【4】使用 sys.stdout.write

原本使用 print()。

優化後使用：

sys.stdout.write("\n".join(outputs))

好處是：

1. 輸出更精準
2. 不會多印最後一個換行
3. 比較適合 Online Judge


【5】保留跳過空白行

如果輸入中有空白行，
程式會直接跳過，
避免 map(int, line.split()) 發生錯誤。


七、偵錯後確認

【1】0 0 可以正確停止

遇到：

0 0

程式會 break，
不會繼續處理。


【2】可以處理多筆輸入

因為程式使用：

for line in sys.stdin

所以可以一直讀到 EOF。


【3】可以正確輸出超過 63 次的情況

如果 63 次內還不能測完，
就會輸出：

More than 63 trials needed.


【4】可以正確處理 ball_count = 1

如果只有 1 顆球，
每次只能一層一層測。

例如：

1 10

答案會是 10。


【5】可以正確處理 floor_count = 0

如果樓層數是 0，
理論上不需要測。

但題目通常用：

0 0

作為結束條件。

其他 ball_count 不是 0、floor_count 是 0 的情況，
程式會在 trials = 1 時判斷 dp[ball_count] >= 0 成立，
回傳 1。

如果題目不會給這種資料，就不影響。


八、時間複雜度

最多跑 63 輪。
每一輪更新 ball_count 個狀態。

時間複雜度：

O(63 * ball_count)

因為 63 是固定常數，
也可以看成：

O(ball_count)


九、空間複雜度

只使用一個 dp 陣列。

空間複雜度：

O(ball_count)


十、總結

這題的重點是反向 DP。

不是直接算「n 層樓需要幾次」，
而是算：

「trials 次最多可以測幾層樓」

只要某一次 trials 的 dp[ball_count] >= floor_count，
那個 trials 就是最少需要的試驗次數。

優化後的程式：

1. 變數名稱更清楚
2. 註解更完整
3. 保留一維 DP
4. 保留 63 次限制
5. 輸出更精準
6. 適合直接交作業
