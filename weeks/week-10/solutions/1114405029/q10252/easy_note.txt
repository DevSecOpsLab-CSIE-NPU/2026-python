easy.py 程式優化與偵錯說明

一、這支程式在做什麼

這題是在解「曼哈頓距離最小化問題」。

給定 n 個點 (x, y)，
要找一個點 (mx, my)，使得：

所有點到這個點的曼哈頓距離總和最小。

曼哈頓距離定義：

|x1 - x2| + |y1 - y2|

同時還要計算：
有幾個點可以達到這個最小距離。


--------------------------------------

二、核心數學觀念（重點）

曼哈頓距離可以拆開：

總距離 =
Σ|xi - mx| + Σ|yi - my|

也就是：

x 跟 y 可以分開處理！

--------------------------------------

三、關鍵結論

【1】最小距離 → 中位數

對於一維：

Σ|xi - m| 最小
→ m 必須是「中位數」

所以：

mx = x 的中位數  
my = y 的中位數  


【2】為什麼用中位數？

因為中位數會讓「左右距離平衡」，
總距離最小。

這是經典性質。


--------------------------------------

四、最佳解個數（最容易錯的地方）

【1】n 是奇數

中位數唯一

→ mx 只有一個  
→ my 只有一個  

所以答案數量：

ways = 1


【2】n 是偶數

中位數不是單一點，而是一段區間：

mx 可以在：

[x[n//2 - 1], x[n//2]]

之間的任何整數

所以：

count_x = xs[mid] - xs[mid-1] + 1


同理：

count_y = ys[mid] - ys[mid-1] + 1


總數：

ways = count_x * count_y


--------------------------------------

五、我做了哪些優化

【1】簡化讀入方式（重要）

原本：

points.append((x, y))

改成：

points = [tuple(map(int, input().split())) for _ in range(n)]

優點：

- 更短
- 更快
- 更 Pythonic


【2】避免重複計算

原本：

n // 2 被多次使用

改成：

mid = n // 2

讓程式更乾淨。


【3】使用 sys.stdout.write

原本用 print()

改成：

sys.stdout.write()

優點：

- 不會多一個換行
- Online Judge 更穩定


【4】增加完整註解

補上：

- 為什麼用中位數
- 為什麼可以拆 x / y
- 為什麼偶數會有區間

這些是老師最愛問的。


--------------------------------------

六、偵錯確認

✔ n = 1 正確  
✔ n = 奇數 正確  
✔ n = 偶數 正確  
✔ 負座標 正確  
✔ 大數值 正確  
✔ 多筆測資 正確  


--------------------------------------

七、時間複雜度

排序：

O(n log n)

計算距離：

O(n)

總體：

O(n log n)


--------------------------------------

八、總結

這題本質是：

「曼哈頓距離最小化 = 中位數問題」

再加上：

「偶數時的區間解數量」

優化後：

1. 程式更簡潔
2. 計算更清楚
3. 可讀性更高
4. 適合交作業
5. 不容易 WA
