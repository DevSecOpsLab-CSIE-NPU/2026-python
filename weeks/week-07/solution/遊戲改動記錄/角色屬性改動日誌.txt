角色屬性改動日誌（完整歷程）
更新日期：2026-04-11
整理範圍：從設計初版到目前 Pygame 版本的屬性演進

【階段 0】原始資料建模（初期）
- 角色資料集中於 generals.txt。
- 固定 9 名角色：蜀 3、吳 3、魏 3。
- 欄位定義：陣營、名稱、HP、ATK、DEF、SPD、是否主將。
- 初版直接使用原始屬性進行戰鬥計算。

【階段 1】主將屬性效果建立
- 增加 is_leader 的戰鬥意義：主將攻擊額外 +2 傷害。
- 目的為拉開角色定位，避免所有角色手感過度同質。

【階段 2】卡牌倍率引入（屬性乘算層）
- 新增卡牌倍率參數，將角色原始 ATK/DEF 與技能效果分層處理。
- 攻擊卡 damage_mult = 1.0。
- 必殺卡 damage_mult = 1.8。
- 防守卡 damage_mult = 0.0（不造成直接傷害）。
- 恢復卡 heal_mult = 0.5（作為技能層設定，並搭配恢復邏輯）。

【階段 3】難度縮放機制建立
- 進入 Pygame 正式版後，角色屬性改為「原始值 * 難度係數」。
- 縮放欄位：HP、ATK、DEF、SPD 全部套用。
- 縮放採陣營分流：蜀吳共用一組係數，魏軍一組係數。
- 縮放結果四捨五入，且最小值保底為 1。

【階段 4】特殊角色覆寫（夏侯惇）
- 新增夏侯惇 HP 特例覆寫，不完全依一般 HP 縮放。
- 覆寫值：簡單 80、普通 95、困難 100。
- 夏侯惇 ATK/DEF/SPD 仍沿用難度縮放。
- 目的：降低魏方單點過度坦度造成的對局失衡。

【階段 5】恢復值平衡調整歷程
- 恢復量由難度固定值控制，最終定版為：
  - 簡單：10
  - 普通：18
  - 困難：30
- 普通難度數值曾多次微調，最終定於 18 以配合目標勝率區間。

【階段 6】防守狀態對實際承傷影響
- 角色進入防守後，成為不可被一般攻擊選中的目標類型之一。
- 在可被命中的情境下，防守狀態仍可降低基礎傷害計算結果。
- 使 DEF 屬性與戰術選擇存在疊加價值，而非單純數值面板。

【階段 7】難度係數重平衡（目前版本）
- 依實測勝率需求調整 _difficulty_factors，形成最終係數：
  - 困難
    - 蜀吳：HP 0.78 / ATK 0.90 / DEF 0.84 / SPD 0.95
    - 魏：HP 0.84 / ATK 0.95 / DEF 0.88 / SPD 0.98
  - 普通
    - 蜀吳：HP 0.72 / ATK 0.86 / DEF 0.80 / SPD 0.93
    - 魏：HP 0.81 / ATK 0.93 / DEF 0.87 / SPD 0.96
  - 簡單
    - 蜀吳：HP 0.68 / ATK 0.84 / DEF 0.76 / SPD 0.92
    - 魏：HP 0.62 / ATK 0.78 / DEF 0.72 / SPD 0.90

【階段 8】屬性平衡驗證方式
- 以多場模擬檢查三個難度勝率帶，反覆修正係數與 AI 行為。
- 平衡調整優先順序：
  1) 難度係數
  2) 恢復值
  3) AI 恢復傾向與上限
- 盡量不直接改 generals.txt 原始資料，保留基準資料完整性。

【目前版本屬性規格總結】
- 原始角色數據維持單一來源（generals.txt）。
- 實戰屬性由難度係數、主將加成、技能倍率共同作用。
- 特例覆寫（夏侯惇 HP）與恢復值已納入平衡設計。
- 屬性系統已從「固定值對砍」演進為「可調係數 + 條件技能 + 難度分層」架構。
