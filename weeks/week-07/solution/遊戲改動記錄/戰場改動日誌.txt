戰場改動日誌（完整歷程）
更新日期：2026-04-11
整理範圍：從遊戲設計初版到目前 Pygame 正式版
主要依據檔案：chibi_battle.py、chibi_battle_visual.py、chibi_battle_pygame.py

【階段 0】純文字戰鬥原型（設計初期）
- 以終端輸出建立戰鬥主流程，先確立三國陣營、攻防計算、波次概念。
- 畫面層僅有文字報表，無戰場圖層、無按鈕、無動畫。
- 初版重點是可運行與可驗證，不追求視覺體驗。

【階段 1】Tkinter 可視化版本（v7）
- 建立雙欄 UI（左側戰況、右側操作），完成「文字版到 GUI」的第一步。
- 新增基本按鈕操作：重新開始、下一回合、自動戰鬥。
- 新增目標下拉選單與操作區塊，戰鬥資訊由 console 轉入視窗。
- 視覺仍以功能為主，尚未有轉盤、倒數、覆蓋層動畫。

【階段 2】Pygame 正式戰場框架
- 轉換為 Pygame 全畫面戰場佈局，建立場景狀態機：lobby、difficulty、name_entry、battle。
- 新增卷軸風格戰場元件（frame、面板、卡牌）並統一 UI 視覺語彙。
- 建立戰場主區 + 右側控制台 + 戰鬥記錄區的固定資訊架構。
- 角色卡全面圖像化：名稱、HP 條、攻防速固定排版，含存活/陣亡視覺差異。

【階段 3】開局戰場流程視覺化
- 新增開局轉盤動畫，決定先攻/後攻。
- 新增開局倒數訊息（5 -> 1 -> 遊戲開始），並同步寫入戰鬥記錄。
- 新增開場覆蓋層動畫（戰鬥開始字樣與淡入淡出效果）。
- 開場流程統一化：重開與新開局都走同一套「重置 -> 轉盤 -> 倒數 -> 進入戰鬥」。

【階段 4】戰場可讀性與操作回饋強化
- 新增傷害飄字效果，受傷時即時顯示並淡出。
- 新增 Toast 系統，支援可調顯示時長，用於提示不可用動作與模式切換。
- 統一戰鬥記錄格式（系統訊息標記、事件文案一致化）。
- 改善目標高亮、出手者高亮與一般單位外框區分，降低誤判。

【階段 5】戰場音效層演進
- 先加入按鍵點擊音與開局提示音。
- 後續拆分為「按鍵音效」與「對局音效」兩條開關路徑。
- 將原難度頁「開場動畫」按鈕替換為「對局音效」按鈕。
- 對局音效擴充為：受傷、恢復、防守、必殺、開局開始音。

【階段 6】輸入鎖與流程安全性
- 實作開局輸入鎖：轉盤中、結果等待中、倒數中，戰場所有按鍵與滾輪都禁用。
- 避免在開局流程中誤觸返回、重開、自動攻擊或其他戰鬥操作。
- 解除鎖定時機固定為倒數結束且正式進入首回合之後。

【階段 7】結算與清場完整化
- 新增勝敗覆蓋層（勝利煙火、失敗視覺與操作按鈕）。
- 重新開始固定重跑先攻轉盤與倒數，不沿用上一局殘留流程。
- 返回大廳加入立即清場：回合、單位、冷卻、待執行事件、浮字、記錄、提示、結算狀態全部重置。
- 目標：保證每次重開或回到大廳後再開局都是乾淨戰場。

【目前版本戰場能力總結】
- 支援完整場景流轉（大廳 -> 難度 -> 名稱 -> 戰鬥 -> 結算）。
- 支援開局轉盤與倒數、戰場輸入鎖、戰鬥視覺回饋與雙音效系統。
- 支援重開與返回大廳的安全重置，避免進度污染下一局。
