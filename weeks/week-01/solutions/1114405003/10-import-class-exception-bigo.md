# 10 模組、類別、例外與 Big-O（最低門檻）

## import 基礎

你必須已經「不需要解釋」就能看懂：

```python
# 從標準函式庫匯入 heapq 模組，常用來處理堆積、Top-N、優先佇列等問題。
import heapq
# deque 是雙端佇列，適合從左右兩端高效率地加入或移除資料。
from collections import deque
```

用途（對應第一章範例）：

- 幾乎所有進階工具

### 補充說明

很多實務程式都不是只靠內建語法完成，而是要先正確匯入對應模組。

- `import 模組名稱`：把整個模組載入，之後用 `模組名稱.功能` 存取。
- `from 模組 import 名稱`：直接匯入特定函式、類別或物件，使用時更短。
- 看到標準函式庫的模組名稱時，先確認它提供的是資料結構、演算法工具，還是輔助函式，再決定要不要直接匯入單一名稱。

## class 與物件（看得懂即可）

```python
# 定義一個簡單的 User 類別。
# __init__ 是建構子，用來在建立物件時初始化屬性。
class User:
    def __init__(self, user_id):
        self.user_id = user_id
```

```python
# 透過點號存取物件屬性，這是物件導向程式最基本的使用方式。
user.user_id
```

用途（對應第一章範例）：

- PriorityQueue Item
- attrgetter
- namedtuple 對照 class

### 補充說明

這裡不要求你寫出複雜的類別設計，但你至少要看懂「資料被包在物件裡」這件事。

- `self` 代表目前這個物件本身。
- 屬性像 `user_id`、`name`、`price` 都是存放在物件裡的資料。
- 當你看到 `obj.attr`，通常就是在讀取或設定某個欄位。
- 在後面章節裡，物件常會被拿來當排序、優先佇列或資料傳遞的容器。

## 例外處理（try / except）

```python
# 嘗試把值轉成整數；如果格式不合法，就進入 except 區塊。
try:
    int(val)
except ValueError:
    # 這裡代表內容不是合法整數字串，例如 'abc'。
    pass
```

用途（對應第一章範例）：

- `filter(is_int, values)`

### 補充說明

例外處理的目的不是「把錯誤吞掉」，而是「針對可能失敗的地方做控制」。

- `try`：包住可能發生例外的程式碼。
- `except ValueError`：只處理特定錯誤類型，避免把其他真正的問題一起掩蓋掉。
- `pass`：表示這個錯誤在目前場景下可以略過，例如把不是整數的值濾掉。

在做資料清洗時，這種寫法很常見，因為輸入資料通常不會完全乾淨。

## 基本 Big-O 觀念（聽得懂即可）

你需要知道：

- O(1), O(N), O(log N)

用途（對應第一章範例）：

- deque vs list
- heap push/pop
- sorted vs nlargest

### 補充說明

這裡的目標不是證明複雜數學，而是讓你有直覺知道「哪種操作通常比較快」。

- `O(1)`：幾乎固定時間，不會因資料變多而明顯變慢。
- `O(N)`：資料越多，時間通常線性增加。
- `O(log N)`：成長比線性慢很多，常見於堆積、二分搜尋等結構。

實務上，這會直接影響你選擇資料結構：

- `deque` 在兩端操作通常比 list 更適合。
- heap 的 push / pop 常比每次完整排序更有效率。
- 當你只需要前幾名時，`nlargest` 通常比先完整排序再切片更合理。

```python
# 範例：如果只要前 3 名，通常不需要把整個清單完整排序。
top3 = heapq.nlargest(3, scores)
```
