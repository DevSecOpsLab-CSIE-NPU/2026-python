## 我問 AI 的問題

### 問題 1：Scent 數據結構選擇
**我的提問**
> "我需要用什麼數據結構來存儲機器人留下的 scent？Scent 需要包含 (x, y, dir)，並且要快速查詢。"

**AI 的建議**
> "使用 `Set[Tuple[int, int, str]]`，這樣 O(1) 查詢時間複雜度。"

**我的採用決定**
- ✅ **採用**：完全同意，這正是我需要的
- **理由**：
  1. O(1) 查詢完美符合需求
  2. 不需要順序，Set 是最佳選擇  
  3. Tuple 的 immutability 確保 hash 安全

### 問題 2：坐標系與方向偏移

**我的提問**
> "地圖坐標是 (0,0) 到 (W,H) 都包含邊界。那方向偏移表應該怎麼寫？北應該是 y+1 還是 y-1？"

**AI 的建議**
```python
DIR_OFFSETS = {
    'N': (0, 1),   # 北增加 y
    'E': (1, 0),   # 東增加 x
    'S': (0, -1),  # 南減少 y
    'W': (-1, 0)   # 西減少 x
}
```

**我的採用決定**
- ✅ **採用**：完全同意
- **理由**：符合數學笛卡爾座標系標準

## 我拒絕的 AI 建議

### 拒絕 1：複雜狀態機

**AI 的建議**
> "使用 State Pattern（狀態機設計模式），為 ALIVE/LOST 創建不同的狀態類。"

**我的拒絕決定**
- ❌ **拒絕**：過度設計
- **理由**：
  1. 簡單的 boolean flag 夠用
  2. 代碼會變得冗長且難以理解
  3. 作業要求簡潔性，不是生產級別代碼

### 拒絕 2：Enum 方向

**AI 的建議**
```python
from enum import Enum
class Direction(Enum):
    NORTH = (0, 1)
    EAST = (1, 0)
    SOUTH = (0, -1)
    WEST = (-1, 0)
```

**我的拒絕決定**
- ❌ **拒絕**：引入不必要的複雜性
- **理由**：
  1. 字符串 'N', 'E', 'S', 'W' 更直觀
  2. Enum 轉換麻煩
  3. 測試中字符串比較更簡單

### 拒絕 3：GIF 重播功能

**AI 的建議**
> "使用 imageio 和 PIL 生成 GIF 動畫回放整個遊戲過程"

**我的拒絕決定**
- ❌ **拒絕**：超出應要求
- **理由**：
  1. 題目要求的 "建議" 而非 "必須"
  2. 增加依賴（imageio, PIL）
  3. 時間成本不值得
  4. 截圖 + 遊戲中重放足夠

## AI 建議不完整的案例

### 案例：Pygame 鍵盤輸入處理

**AI 的初始建議**
```python
if event.type == KEYDOWN:
    if event.key == K_l:
        robot.rotate_left()
```

**問題**
- 沒有檢查 robot 是否 LOST
- 沒有檢查 robot 是否存在

**我的修正**
```python
if event.type == KEYDOWN:
    if event.key == K_l:
        if self.current_robot and not self.current_robot.lost:
            self.simulator.execute_command(self.current_robot, 'L')
            self.command_history += 'L'
```

**改進點**
1. ✅ 檢查 current_robot 存在
2. ✅ 檢查 LOST 狀態（不允許操作）
3. ✅ 通過 simulator 執行（而非直接調用）
4. ✅ 記錄命令歷史

## 學習心得

1. **好的 AI 協助**：幫助快速決策，但不盲目跟從
2. **批判性思考**：評估建議是否符合實際需求
3. **適度應用**：選擇對專案有利的建議，拒絕過度設計
4. **實踐驗證**：AI 建議需要在實作中驗證是否可行
